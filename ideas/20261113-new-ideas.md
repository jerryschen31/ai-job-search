# New Open-Source Project Ideas for Jerry Chen — 2026-11-13

## Momentum signals (last ~3–4 months)

- **MCP 2026-07-28 spec shipped** (RC locked May 21, final July 28). Per the [official release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/): the `initialize` handshake and `Mcp-Session-Id` are gone (stateless core); auth servers must return `iss` (RFC 9207) and Dynamic Client Registration is deprecated in favour of Client ID Metadata Documents; a formal extensions framework now hosts Tasks, MCP Apps and **Enterprise Managed Authorization**. Claude support: [Bringing MCP 2026-07-28 to Claude](https://claude.com/blog/bringing-mcp-2026-07-28-to-claude). Every existing bio MCP server and gateway built on the sessionful design needs review.
- **Agent Skills became an open standard with org-wide management.** Anthropic's [enterprise skills guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise) tells admins to run a security review *and an evaluation suite* before approving skills. Skill-eval tooling is appearing ([adewale/skill-eval-harness](https://github.com/adewale/skill-eval-harness), pushed 2026-11-06) but none targets regulated or bio work.
- **Regulatory AI guidance is still in "draft + principles" mode.** FDA's Jan 2025 credibility-framework draft is the operative document (I found no evidence of a final version); FDA and EMA jointly published 10 non-binding [Guiding Principles of Good AI Practice in Drug Development](https://www.nsf.org/gb/en/life-science-regulatory-news/fda-and-ema-release-guiding-principles-of-good-ai-practice-in-drug-development) on 2026-01-14, including "data governance and documentation" and "life cycle management". Sponsors need evidence tooling now.
- **Bioinformatics-agent ecosystem is booming but is collection-heavy:** skills catalogues ([SciAgent-Skills](https://github.com/jaechang-hits/SciAgent-Skills) 389★, [awesome-genomic-skills](https://github.com/GoekeLab/awesome-genomic-skills) 133★), benchmarks ([BixBench](https://github.com/Future-House/BixBench) 153★), and a popular literature/variant MCP ([biomcp](https://github.com/genomoncology/biomcp) 679★). Operational, qualification and governance layers are thin.

Note: GitHub search hit its API rate limit late in research, so prior-art coverage rests on the searches listed per idea. Star counts were fetched 2026-11-13/14.

## 1. `omics-mcp-gateway` — Enterprise-managed-auth MCP gateway with per-tool RBAC for biotech data

**Pitch:** A small, spec-2026-07-28-native gateway that fronts internal bioinformatics MCP servers (S3, LIMS, Athena, Nextflow) with OIDC/Enterprise Managed Authorization, per-tool allow/deny policy, read-only defaults and structured audit logs.

**Problem & who needs it:** Biotech IT and platform teams want scientists to use Claude Code/Claude with internal data, but each MCP server ships its own (or no) auth. Security will not approve "stdio server with my AWS keys" for GxP-adjacent data.

**Why now:** The 2026-07-28 spec made servers stateless and added Enterprise Managed Authorization plus `iss` validation and CIMD ([release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/)); gateways built for the old spec are being orphaned (see prior art).

**Prior art & gap:**
- [hyprmcp/mcp-gateway](https://github.com/hyprmcp/mcp-gateway) — 92★, OAuth proxy with DCR plus request logging, but **archived Apr 29, 2026**, with no mention of the 2026-07-28 spec, per-tool RBAC, or AWS IAM Identity Center.
- [Nova-Hunting/nova-proximity](https://github.com/Nova-Hunting/nova-proximity) — 306★, a *scanner* for MCP/skills, not an enforcement point.
- [mcp-oauth-proxy variants](https://github.com/exalsch/mcp-oauth-proxy) — 1–2★ each, wrappers only.
Gap: no maintained, policy-as-code gateway aimed at regulated science with AWS identity integration.
(Complements yesterday's `agent-ledger` — that records sessions client-side; this enforces authz server-side. Different layer.)

**Why Jerry:** IAM/Terraform/AWS depth, GxP mindset (least privilege, audit), Claude Code/MCP daily use at Genentech.

**MVP (3 weeks):** Python (FastAPI/Starlette) reverse proxy; OIDC validation incl. `iss`; YAML policy (tool allowlist, argument constraints, read-only mode); JSON-lines audit log to S3; Terraform module for ECS/Lambda deploy behind IAM Identity Center; demo with an S3-read MCP server.

**Career angle:** Concrete artifact for "AI platform / security-minded AI engineering in regulated enterprise" roles; shows current protocol fluency.

## 2. `skill-oq` — Operational qualification for Claude Code skills (bioinformatics golden tasks + evidence pack)

**Pitch:** Treat each Agent Skill as a controlled configuration item: run golden bioinformatics tasks with deterministic graders against pinned model versions and emit an OQ-style evidence report (skill hash, model ID, pass/fail, deviations).

**Problem & who needs it:** Orgs deploying skills org-wide are told to maintain an evaluation suite, but regulated teams also need *versioned, signed-off evidence* that a skill still works after a skill edit or model change.

**Why now:** Anthropic's [enterprise skills guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise) recommends vetting and evaluation before approval; FDA/EMA principles stress [life-cycle management and risk-based performance assessment](https://www.nsf.org/gb/en/life-science-regulatory-news/fda-and-ema-release-guiding-principles-of-good-ai-practice-in-drug-development).

**Prior art & gap:**
- [adewale/skill-eval-harness](https://github.com/adewale/skill-eval-harness) — 79★; paired with/without-skill lift and stats, example is PR review; no bio or regulated content (fetched README).
- [DeadHead04/skillEd](https://github.com/DeadHead04/skillEd) — 72★, generic regression CLI/MCP.
- [Future-House/BixBench](https://github.com/Future-House/BixBench) — 153★ benchmark, not a per-skill qualification workflow.
- [jaechang-hits/SciAgent-Skills](https://github.com/jaechang-hits/SciAgent-Skills) — 389★ skills catalogue, no qualification.
Gap: bio-specific golden tasks + GxP-style evidence output. Build on (or adapt) an existing harness rather than reinventing it.

**Why Jerry:** Validation (IQ/OQ/PQ) background plus Genentech skills/AI-champion work.

**MVP (3 weeks):** CLI in Python; `skill-oq.yaml` spec (intended use, risk tier, tasks); 8–10 golden tasks on tiny public data (VCF filtering, FASTQ QC summary, samplesheet generation); deterministic graders; Markdown/PDF report with hashes; GitHub Action.

**Career angle:** Directly the "validated GenAI in pharma" story; differentiates from generic LLM-eval portfolios.

## 3. `omics-attest` — Signed provenance + S3 Object Lock "evidence vault" for pipeline outputs

**Pitch:** After a Nextflow/Batch run, hash outputs, create in-toto/Sigstore attestations (inputs, container digests, params) and write them to a compliance-mode Object Lock bucket, with a `verify` command that proves nothing changed.

**Problem & who needs it:** ALCOA+ data integrity for analysis results is usually "trust the bucket versioning". Auditors want tamper-evidence and traceability from result back to pipeline version and containers.

**Why now:** GitHub/Sigstore attestations are mainstream in software supply chains ([GitHub artifact attestations](https://github.blog/2024-05-02-introducing-artifact-attestations-now-in-public-beta/)), and a practitioner post notes [versioning alone is not tamper-evidence; Object Lock is the control](https://blog.quilt.bio/cryptographic-signing-s3-data-provenance). Regulators emphasize data governance and documentation (FDA/EMA principles above).

**Prior art & gap:** A web search for Nextflow + sigstore/in-toto + Object Lock found only the individual pieces and nothing bio-specific; yesterday's [nf-prov](https://github.com/nextflow-io/nf-prov) records provenance but does not sign it or enforce immutable storage. I could not run a GitHub-side search for this (rate limit), so re-check before starting.

**Why Jerry:** Built a GxP-qualified Bioinformatics Cloud and 7,000+-sample pipelines; Terraform/S3/IAM fluency.

**MVP (3 weeks):** Python CLI + Terraform module (Object Lock bucket, KMS, bucket policy denying delete); cosign/Sigstore for signing; consume nf-prov output as predicate input; `verify` and HTML report; example on a public nf-core test dataset.

**Career angle:** Concrete GxP data-integrity engineering demo, bridging cloud infra and regulated science.

## 4. `omics-finops` — Per-sample, per-process cost attribution for Nextflow on AWS Batch

**Pitch:** Join Nextflow trace files with AWS Cost and Usage Report/Spot price history in Athena to answer "what did this cohort cost, which process wastes money, and where are Spot interruptions hurting?"

**Problem & who needs it:** Platform teams get a single Batch bill; PIs want cost per sample/project; nobody can see over-provisioned `memory`/`cpus` directives versus actual usage.

**Why now:** Pipeline volumes and agent-driven re-runs raise cloud bills; cost visibility is a recurring gap in scientific platforms. (I found no dated momentum metric for this specific niche; the case rests on the gap below.)

**Prior art & gap:** The only GitHub hit for Nextflow cost work was [nttg8100/nextflow-cost-optimization](https://github.com/nttg8100/nextflow-cost-optimization) — 0★, proof-of-concept (2026-02). Seqera's commercial platform covers some of this but is not OSS. Related but distinct: yesterday's `nf-ops-mcp` mentions cost triage inside an MCP server; this is a data-model/Athena/dashboard FinOps layer it could consume.

**Why Jerry:** AWS Batch/RDS/Redshift, Terraform, cloud cost ownership on previous platforms.

**MVP (2–3 weeks):** Terraform for Athena tables over CUR + trace exports; Python loader normalizing trace → cost allocation tags; SQL views (cost/sample, cost/process, right-sizing suggestions); small Streamlit or static HTML report; optional MCP read-only tool.

**Career angle:** Infra-for-science credibility; strong talking point for platform/cloud roles in biotech.

## 5. `manifest-sentry` — LIMS ↔ samplesheet ↔ FASTQ reconciliation, with an MCP front end

**Pitch:** A deterministic checker that cross-validates the LIMS sample manifest, the pipeline samplesheet, and the files actually landed on S3 (existence, checksums, read-pair completeness, metadata consistency), exposed as CLI and MCP tool so an agent can explain and fix mismatches.

**Problem & who needs it:** Most failed or mis-attributed NGS runs begin with metadata errors at handoff. Schema validators check the shape of one file, not agreement across systems.

**Why now:** Agents are being given pipeline-launch ability; a pre-flight gate that returns structured findings is the safety control that makes this acceptable. Bio-agent skill/MCP ecosystem growth listed in the signals above.

**Prior art & gap:**
- [nextflow-io/nf-schema](https://github.com/nextflow-io/nf-schema) — 58★; validates samplesheets against JSON schema, single-file scope.
- [colindaven/rusty_samplesheet](https://github.com/colindaven/rusty_samplesheet) — 2★, Illumina SampleSheet validation, last push 2022.
- [zavora-ai/mcp-lims](https://github.com/zavora-ai/mcp-lims) — 1★, a toy LIMS server, food-safety focus.
Gap: cross-system reconciliation plus agent-friendly output.

**Why Jerry:** Led end-to-end sample data pipelines (7,000+ samples), LIMS/database/cloud work at Factorial and Encoded.

**MVP (2–3 weeks):** Python package; adapters for CSV manifest, Illumina SampleSheet v2, nf-core samplesheet, S3 listing; rule engine with severity codes; JSON + human report; MCP server with 3 tools; synthetic test dataset with seeded errors.

**Career angle:** Shows safe-agent design (deterministic gates) in a domain Jerry knows; easy demo.

## 6. `bio-mcp-contracts` — Golden-query contract tests for biological-database MCP servers

**Pitch:** A nightly-runnable suite that checks bio MCP servers (UniProt/ClinVar/literature wrappers) return correct, stable answers for pinned golden queries, and flags upstream API drift, silent truncation, and spec-2026-07-28 behaviour changes.

**Problem & who needs it:** Teams adopting community bio MCP servers have no way to know when an upstream API change makes an agent quietly give wrong or empty answers.

**Why now:** The spec rewrite means many servers will change behaviour in the coming months ([release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/)); bio servers are proliferating (e.g. [biomcp](https://github.com/genomoncology/biomcp) 679★, pushed 2026-11-10; [biocontext-ai/knowledgebase-mcp](https://github.com/biocontext-ai/knowledgebase-mcp) 32★).

**Prior art & gap:** [modelcontextprotocol/conformance](https://github.com/modelcontextprotocol/conformance) — 146★, tests protocol conformance, not data correctness. Skill-eval tools (idea 2) test skills, not the data servers. Gap: domain-level contract tests with recorded fixtures and drift reports. Caveat: this is the thinnest-moat idea of the six; value comes from curated golden sets.

**Why Jerry:** Bioinformatics domain knowledge to write correct golden answers; MCP experience; CI/automation.

**MVP (2 weeks):** pytest plugin that launches an MCP server (stdio/HTTP), replays YAML queries, compares via tolerant matchers; 30 golden queries across 3 public servers; GitHub Actions nightly + issue on drift; Markdown drift report.

**Career angle:** Open-source utility others can adopt quickly; good entry for contributing upstream to bio MCP projects.

## Summary

Today's six ideas are: **`omics-mcp-gateway`** (spec-2026-07-28 MCP gateway with per-tool RBAC for biotech data), **`skill-oq`** (GxP-style operational qualification and evidence reports for Claude Code skills on bioinformatics tasks), **`omics-attest`** (Sigstore-signed provenance plus S3 Object Lock evidence vault), **`omics-finops`** (per-sample/process cost attribution for Nextflow on AWS Batch), **`manifest-sentry`** (LIMS/samplesheet/FASTQ reconciliation with an MCP front end), and **`bio-mcp-contracts`** (golden-query contract tests for biological-database MCP servers). They cover agentic-AI × bioinformatics (1, 5, 6), GxP/regulated AI tooling (2, 3), and cloud infrastructure for science (3, 4), and avoid algorithm development. Weak spots: ideas 3 and 4 have thin dated momentum evidence and I could not complete GitHub searches for 3 after hitting the rate limit; idea 6 has the thinnest moat.
