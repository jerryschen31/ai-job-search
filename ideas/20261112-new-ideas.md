## 1. `agent-ledger` — Part 11-style tamper-evident audit trail for Claude Code / MCP sessions

**Pitch:** A hook + MCP-proxy layer that records every agent prompt, tool call, file diff, and human approval into a hash-chained, ALCOA+-mapped ledger with e-signature-style review sign-off.

**Problem & who needs it:** Regulated teams (GxP software, bioinformatics, QA) want to use coding agents but cannot show an inspector what the agent did, who approved it, or that the record is unaltered. Quality/validation leads and platform teams need it.

**Why now:** FDA/EMA's Jan 2026 principles stress [traceable, verifiable data provenance and GxP adherence](https://www.brownejacobson.com/insights/ema-and-fda-guiding-principles-for-ai-in-drug-development-a-review); the MCP 2026-07-28 revision adds standardized auth and Tasks ([summary](https://www.descope.com/blog/post/july-2026-mcp-revision)), making an interception point more stable.

**Prior art & gap:**
- [disler/claude-code-hooks-multi-agent-observability](https://github.com/disler/claude-code-hooks-multi-agent-observability) (1568★): real-time monitoring, not tamper-evident or compliance-mapped.
- [Trusted-Autonomy/TrustedAutonomy](https://github.com/Trusted-Autonomy/TrustedAutonomy) (8★, 0.17.0-alpha): SHA-256 hash-chained log and human review, but no GxP/Part 11 mapping and a self-described unaudited security model.
- [hugoii/llm-agent-audit](https://github.com/hugoii/llm-agent-audit) (62★): authorization reviews, not records.
Gap: no ALCOA+/Part 11 control mapping, no signature manifestations, no inspector-readable export.

**Why Jerry:** He led GxP-qualified Bioinformatics Cloud validation and builds with Claude Code daily at Genentech; this is exactly the missing artifact he would need internally.

**MVP (2–4 wks):** Claude Code hooks → append-only JSONL with SHA-256 chaining and periodic anchoring to S3 Object Lock; `ledger verify` CLI; a control-mapping table (ALCOA+, Part 11 §11.10/11.50/11.70) and a PDF/HTML session report. Stack: Python, Typer, Pydantic, boto3, Jinja2. Stretch: MCP stdio proxy.

**Career angle:** Concrete, demoable evidence of "AI adoption in regulated enterprise" — directly relevant to biotech-AI engineering, AI governance, and validation roles.

## 2. `csa-evidence` — Docs-as-code assurance records from git/PRs (FDA CSA / GAMP 5 style)

**Pitch:** Generate risk-based assurance evidence (risk assessment, unscripted/scripted test rationale, traceability, release record) automatically from a repo's PRs, CI results, and a small risk config.

**Problem & who needs it:** Teams adopting CSA still hand-write validation documents in Word. Scientific-software teams in pharma need lightweight, defensible records tied to actual commits.

**Why now:** FDA's [CSA final guidance](https://www.nsf.org/life-science-regulatory-news/fda-final-guidance-computer-software-assurance-csa) (Sept 2025; updated Feb 2026), and the drafted [revised Annex 11](https://www.gmp-compliance.org/gmp-news/drafts-of-eu-gmp-guideline-annex-11-annex-22-and-chapter-4-released-for-comment). Note FDA's CSA guidance scope is device production/quality system software; pharma teams use it as an analogue, so the tool should stay framework-agnostic.

**Prior art & gap:** Searches turned up only tiny repos: [AliakseiT/dearauditor-qms-baseline](https://github.com/AliakseiT/dearauditor-qms-baseline) (17★, QMS baseline), [alianisreyesr/csa-assurance-planner](https://github.com/alianisreyesr/csa-assurance-planner) (0★), [alianisreyesr/csv-evidence-tracker](https://github.com/alianisreyesr/csv-evidence-tracker) (2★), [sandipbthorat/CSACompass](https://github.com/sandipbthorat/CSACompass) (0★). No maintained tool generates evidence from git history.

**Why Jerry:** Global Implementation Lead for FCS Express validation and project lead of a GxP-qualified cloud — he knows what an auditor actually reads.

**MVP:** YAML risk register per component → GitHub Action collecting PR approvals, test results (JUnit), and commit SHAs → rendered Markdown/PDF assurance package + traceability matrix; optional Claude-drafted rationale text with human sign-off flagged. Stack: Python, GitHub Actions, Jinja2, WeasyPrint.

**Career angle:** Positions him as the person who modernizes CSV for AI-era delivery; strong fit for validation-engineering and regulated-platform leads.

## 3. `cou-dossier` — Context-of-Use credibility dossier generator for ML/LLM models (FDA credibility + Annex 22 checks)

**Pitch:** A CLI that turns a model card, eval results, and data manifests into a structured credibility-assessment dossier keyed to context of use and risk, plus an Annex 22-style checklist (static/deterministic, test-data independence, drift monitoring).

**Problem & who needs it:** Sponsors using AI to support regulatory decisions must document context of use, risk, and evidence; most do it ad hoc.

**Why now:** FDA's [Jan 2025 draft AI credibility guidance](https://www.gmp-compliance.org/gmp-news/new-fda-guidance-for-industry-draft-on-ai) centers on context of use and risk (sources indicate it was not finalized as of mid-2026); [draft Annex 22](https://www.learnsignal.com/blog/eu-gmp-annex-22-artificial-intelligence-draft-requirements/) targets AI in GMP; FDA/EMA principles of Jan 2026.

**Prior art & gap:** GitHub search for "model credibility", "Annex 22" found only zero-star or unrelated repos (e.g. [avenzia/annex22-quiz](https://github.com/avenzia/annex22-quiz), 0★; [abelsalgado-arch/pharma-ai-validation](https://github.com/abelsalgado-arch/pharma-ai-validation), 0★). Open niche. Caveat: drafts can change, so make the checklist data-driven (YAML) and versioned.

**Why Jerry:** GxP validation background plus RAG/agentic coursework; practical, not algorithmic — documentation and evidence plumbing.

**MVP:** JSON Schema for COU/risk/evidence; templates for FDA 7-step-style and Annex 22 checks; ingest of model cards and eval metrics; HTML/PDF dossier; sample dossier for an LLM-based literature triage tool. Stack: Python, Pydantic, Jinja2, pytest.

**Career angle:** Differentiates him in "AI governance in pharma" roles, an area where few engineers can speak both regulatory and implementation language.

## 4. `nf-ops-mcp` — MCP server for Nextflow run operations on AWS Batch (triage, cost, lint, resume)

**Pitch:** Let an agent diagnose failed or slow Nextflow runs by reading trace/report files, Batch job states, and CloudWatch logs, and propose `-resume` / resource-tuning changes.

**Problem & who needs it:** Bioinformatics platform engineers spend time on failure triage and over-provisioned processes; agents now author Nextflow but don't operate it.

**Why now:** Nextflow [26.10 adds agents](https://docs.seqera.io/nextflow/agent) (preview) and [26.04 strict syntax/records](https://docs.seqera.io/changelog/nextflow/v26.04.5) that give agents precise errors; MCP's Tasks extension fits long-running pipelines ([summary](https://flaviocopes.com/mcp-2026-07-28-stateless/)).

**Prior art & gap:** [awslabs/aws-healthomics-tools](https://github.com/awslabs/aws-healthomics-tools) (43★) covers HealthOmics, not self-managed Batch. [adamrtalbot/mcp-nextflow](https://github.com/adamrtalbot/mcp-nextflow) (2★, last push 2025-03), [ajibadedapo/flowproof-mcp](https://github.com/ajibadedapo/flowproof-mcp) (2★), [bmds-tue/nf-claw](https://github.com/bmds-tue/nf-claw) (4★; pipeline library + run checks, MIT) are small. Gap: operational analytics (trace-based right-sizing, Spot/failure analysis) on Batch.

**Why Jerry:** Built cloud genomics at Encoded (7,000+ samples) and Bioinformatics Cloud on AWS Batch/S3/ECR/IAM with Terraform.

**MVP:** MCP tools: `parse_trace`, `explain_failure` (exit codes + `.command.log`), `suggest_resources`, `estimate_cost`, `batch_job_status`; read-only IAM by default; sample dataset using nf-core/demo. Stack: Python MCP SDK, boto3, pandas, pytest, Terraform for a test Batch env.

**Career angle:** Shows agentic-infra-for-science depth that maps to platform and AI-engineering roles at biotech/cloud vendors.

## 5. `gxp-landing-zone` — Terraform module + automated IQ/OQ evidence for a bioinformatics AWS environment

**Pitch:** Opinionated Terraform for a qualified-ready bio-compute environment (Batch, S3 with Object Lock, KMS, IAM boundaries, CloudTrail) that emits machine-generated installation/operational qualification evidence.

**Problem & who needs it:** Biotech startups and R&D IT teams need a defensible cloud baseline; today each writes IQ/OQ scripts from scratch.

**Why now:** AWS pushing HealthOmics and agent tooling ([Kiro Power](https://aws.amazon.com/about-aws/whats-new/2026/01/aws-healthomics-introduces-kiro-plugin-for-bioinformatics-workflow-development)) increases cloud-native regulated workloads; revised Annex 11 emphasizes lifecycle, supplier oversight, audit trails ([draft summary](https://www.gmp-compliance.org/gmp-news/drafts-of-eu-gmp-guideline-annex-11-annex-22-and-chapter-4-released-for-comment)).

**Prior art & gap:** `gh search repos "aws gxp"` returned only an empty 2018 repo ([Susantkm/AWSGxP](https://github.com/Susantkm/AWSGxP), 0★). Not a guarantee nothing exists elsewhere (AWS whitepapers/blogs), but no maintained open-source module found. [aws-samples/aws-healthomics-tutorials](https://github.com/aws-samples/aws-healthomics-tutorials) (96★) is unrelated to qualification.

**Why Jerry:** Project Lead of GxP-qualified Bioinformatics Cloud; Terraform/AWS is primary stack.

**MVP:** Module with 3 profiles; `terraform test` + AWS Config/Steampipe-style checks mapped to requirement IDs; evidence bundle (plan hash, resource inventory, test results, signed manifest). Stack: Terraform, Python, GitHub Actions, OIDC.

**Career angle:** Publicly demonstrates the qualified-cloud expertise that is his core differentiator for cloud/platform roles in pharma.

## 6. `sc-agent-crate` — Single-cell analysis agent that exports replayable RO-Crate provenance

**Pitch:** A Claude Code skill + MCP server that runs scanpy/AnnData QC and clustering steps in a sandbox, logs every parameter and package version, and exports a Workflow Run RO-Crate that reproduces the analysis.

**Problem & who needs it:** Scientists using agents for exploratory single-cell analysis can't later explain or reproduce what the agent ran; core facilities and translational teams need the record.

**Why now:** Bio-agent repos are popular ([ScienceClaw](https://github.com/beita6969/ScienceClaw) 1028★), RO-Crate tooling is active ([ResearchObject/ro-crate](https://github.com/ResearchObject/ro-crate) 167★, pushed 2026-11-13; [nextflow-io/nf-prov](https://github.com/nextflow-io/nf-prov) 31★), and FDA/EMA stress [traceable analytical decisions](https://www.brownejacobson.com/insights/ema-and-fda-guiding-principles-for-ai-in-drug-development-a-review).

**Prior art & gap:** [biocontext-ai/anndata-mcp](https://github.com/biocontext-ai/anndata-mcp) (7★) exposes AnnData but not provenance; [ResearchObject/ro-crate-py](https://github.com/ResearchObject/ro-crate-py) (92★) is the export library to reuse; nf-prov serves Nextflow only. No agent-session-to-RO-Crate bridge found.

**Why Jerry:** Head of Bioinformatics at Factorial (single-cell genomics platform); Ph.D. computational biology; Claude Code skills.

**MVP:** MCP tools for load/QC/normalize/cluster with fixed-seed, logged calls; session recorder; RO-Crate export via ro-crate-py; validate with [crs4/rocrate-validator](https://github.com/crs4/rocrate-validator) (28★); demo on a public PBMC dataset. Stack: Python, scanpy, anndata, MCP SDK, ro-crate-py.

**Career angle:** Combines agentic AI with bioinformatics reproducibility — an easy story for biotech-AI and data-platform interviews.

## Summary

Today's six ideas: **agent-ledger** (Part 11-style audit trail for Claude Code/MCP sessions), **csa-evidence** (assurance records generated from git/PRs), **cou-dossier** (context-of-use credibility dossier and Annex 22 checks for ML/LLM models), **nf-ops-mcp** (MCP server for operating Nextflow on AWS Batch), **gxp-landing-zone** (Terraform bio-compute baseline with automated IQ/OQ evidence), and **sc-agent-crate** (single-cell agent with RO-Crate provenance). They cover agentic-AI × bioinformatics (nf-ops-mcp, sc-agent-crate), GxP/regulated-AI tooling (agent-ledger, csa-evidence, cou-dossier), and cloud/infra for science (gxp-landing-zone, nf-ops-mcp). None leans on novel algorithms, and GitHub searches found no well-maintained (>200★) repo already doing any of them. Caveats: regulatory draft status (Annex 22, FDA credibility) rests on secondary sources, and my GitHub searches were keyword-based, so verify before committing to one.
