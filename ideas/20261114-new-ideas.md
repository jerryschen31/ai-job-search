# New Open-Source Project Ideas for Jerry Chen — 2026-11-14

## Momentum signals (last ~3–4 months)
- **MCP 2026-07-28 spec** is the biggest protocol change since launch: stateless core (no `initialize`/`Mcp-Session-Id`), Tasks moved to an extension (`tasks/get`, `tasks/update`), Multi Round-Trip Requests replacing server-initiated elicitation, RFC 9207 `iss` validation, and DCR deprecated in favor of Client ID Metadata Documents. Source: [official changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog). Critique that Tasks ships without a normative auth requirement: [Mindgard](https://mindgard.ai/blog/zero-auth-zero-trust-the-must-that-never-made-it-into-mcps-new-tasks-extension) (third-party, unverified).
- **AWS HealthOmics is moving fast**: Nextflow 26.04 with strict-syntax parser on by default and an "agent logging mode" ([AWS](https://aws.amazon.com/about-aws/whats-new/2026/06/aws-healthomics-nextflow-version-26-04/)); Nextflow v26.10 with GA static typing, runtime Nextflow config, `outputUriPrefixMode`, third-party container registries, and `omicsResourceFallbackOrder` (all in the [doc history](https://docs.aws.amazon.com/omics/latest/dev/doc-history.html), Oct–Nov 2026). Variant/annotation stores closed to new customers on 2025-11-07, with [S3 Tables/Iceberg as the migration path](https://docs.aws.amazon.com/omics/latest/dev/variant-store-availability-change.html).
- **Bio agent-skill ecosystem is exploding but unvalidated**: [GoekeLab/awesome-genomic-skills](https://github.com/GoekeLab/awesome-genomic-skills) (134★), [ssinder/bioinformatics-agent-skills](https://github.com/ssinder/bioinformatics-agent-skills) (75★, pushed 2026-10-27), [SteveTangent/goose-bio-skills](https://github.com/SteveTangent/goose-bio-skills) (64★).
- **Regulatory**: FDA/EMA joint 10 AI principles for drug development (Jan 2026) per [PharmaSource](https://pharmasource.global/content/policy-briefing/fda-and-ema-issue-joint-ai-principles-for-drug-development/); EU GMP Annex 22 and FDA's AI credibility guidance were still reported as drafts as of Oct 2026 (secondary sources, e.g. [PharmTech](https://www.pharmtech.com/view/pharmas-next-ai-problem-is-authority)) — verify against EMA/FDA pages.

Note: these ideas deliberately avoid the 11/12 and 11/13 sets (agent-ledger, csa-evidence, cou-dossier, nf-ops-mcp, gxp-landing-zone, sc-agent-crate, omics-mcp-gateway, skill-oq, omics-attest, omics-finops, manifest-sentry, bio-mcp-contracts).

## 1. `bioskill-lint` — Static validator for bioinformatics agent skills
**Pitch:** `eslint` for `SKILL.md` files: checks that every tool, version, flag, container, and reference genome a bio skill mentions actually exists.

**Problem & who needs it:** Skill collections for genomics are multiplying, and LLM-written skills routinely cite nonexistent flags, retired Bioconda versions, or dead container tags. Anyone adopting community skills inside a biotech (or curating one, as Jerry does for ~100 trainees) has no automated gate.

**Why now:** Three independent bio-skill repos are active in the last 2 months (links above), plus an "awesome" index at 134★ — a quantity-over-quality phase that precedes a tooling phase.

**Prior art & gap:** The repos above are content collections; [variomeanalytics/bioinformatics-agent-skills](https://github.com/variomeanalytics/bioinformatics-agent-skills) (63★) is an MCP knowledge graph of 78 workflows, not a validator. Searches for skill lint/validate tools (`SKILL.md` lint, bioconda skill validate, biocontainers mcp) returned nothing on GitHub. `skill-oq` (11/13) qualifies skill *behavior* via golden tasks; this checks skill *content* statically and cheaply, with no model calls.

**Why Jerry:** Claude Code skills author + trainer; Bioconda/NGS tool familiarity (BWA, GATK, Mutect2, SAMtools); Python packaging.

**MVP (2–4 weeks):** Python CLI + GitHub Action. Parse skill frontmatter and code fences; resolve tools/versions against Bioconda/BioContainers APIs; `--help` flag verification inside a pinned container; link/URL check; rule IDs with SARIF output. Run it against the three repos above and publish a "lint report card".

**Career angle:** Concrete AI-governance tooling for skill-based agents; the report-card post is a credible visibility piece for AI-champion roles in pharma.

## 2. `nf-strict-migrate` — Agent-assisted migration to Nextflow strict syntax / static typing with HealthOmics preflight
**Pitch:** Claude Code skill + CLI that migrates DSL2 pipelines to 26.04 strict syntax and 26.10 typed records, then preflights them for AWS HealthOmics.

**Problem & who needs it:** Strict syntax is now the default parser, and HealthOmics enforces it; legacy in-house pipelines break at launch. HealthOmics also has platform-specific traps (container registries, resource directives, output prefixing, parameter templates).

**Why now:** [HealthOmics Nextflow 26.04 release](https://aws.amazon.com/about-aws/whats-new/2026/06/aws-healthomics-nextflow-version-26-04/); v26.10 GA static typing and new run options in the [doc history](https://docs.aws.amazon.com/omics/latest/dev/doc-history.html).

**Prior art & gap:** [nf-core/strict-syntax-health](https://github.com/nf-core/strict-syntax-health) (7★) only *tracks* lint health across nf-core; [lescai-teaching/nextflow_strict_syntax_2026](https://github.com/lescai-teaching/nextflow_strict_syntax_2026) (0★) is a workshop. `nextflow lint` reports problems but does not migrate or check HealthOmics constraints. [awslabs/mcp](https://github.com/awslabs/mcp) (9.9k★) ships an `aws-healthomics-mcp-server` for run management — not migration or preflight.

**Why Jerry:** Led GxP Bioinformatics Cloud on AWS; Batch/ECR/IAM depth; Claude Code engineering.

**MVP:** Wrap `nextflow lint` JSON output; an agent loop applies fixes per rule with a diff-per-rule commit; a deterministic preflight rule set (private-ECR/registry check, `outputUriPrefixMode`, resource fallback directive, parameter template presence); validate on 5–10 public nf-core pipelines; before/after lint-count table.

**Career angle:** Demonstrates agent-assisted code modernization with deterministic guardrails — directly relevant to regulated change control.

## 3. `omics-iceberg` — Production-grade VCF → S3 Tables (Iceberg) cohort store, as Terraform + validation harness
**Pitch:** The replacement for HealthOmics variant stores that a regulated team can actually deploy: Terraform, loader, schema versioning, and round-trip verification.

**Problem & who needs it:** Teams with variant stores must migrate; new teams need a queryable cohort store. AWS provides a reference Glue ETL and example DDL but leaves infra, IAM, lifecycle, and data-integrity proof to the user.

**Why now:** The closure and migration guidance ([AWS docs](https://docs.aws.amazon.com/omics/latest/dev/variant-store-availability-change.html)) pushes everyone to S3 table buckets + Athena.

**Prior art & gap:** [aws-samples/aws-healthomics-tutorials](https://github.com/aws-samples/aws-healthomics-tutorials) (96★, contains `glue-variant-etl`) is the closest — a tutorial sample, not a packaged module. GitHub searches for "vcf iceberg", "vcf athena" and "vcf parquet" found nothing substantial. Differentiator: Terraform module, IAM least-privilege roles, and a verifier that proves row-level fidelity (count/checksum vs source VCFs) — the OQ-style evidence GxP teams need.

**Why Jerry:** Built cloud genomics data stack over 7,000+ samples (Encoded), Redshift/RDS/S3/IAM, Terraform, Python; Huron Athena/S3 work.

**MVP:** Terraform for table bucket + namespace + Lake Formation grants; PyIceberg loader using the AWS example schema; Athena query cookbook (per-gene, per-sample); fidelity verifier on 1000 Genomes subset; cost notes.

**Career angle:** Cloud-for-science infrastructure with validation evidence; fits Genentech-style platform roles.

## 4. `duo-guard` — Consent / data-use-ontology enforcement for AI agents querying genomic datasets
**Pitch:** A policy layer that reads GA4GH DUO codes (and simple internal consent tags) and blocks or annotates agent queries that exceed a dataset's permitted use.

**Problem & who needs it:** Agents will increasingly pull from controlled-access cohorts. Permitted-use limits (e.g., "disease-specific research only", "no commercial use") live in metadata no agent checks.

**Why now:** MCP's auth hardening and Client ID Metadata Documents ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)) make per-user policy decisions at the server practical; agentic data access in pharma is mainstream.

**Prior art & gap:** GitHub searches for "ga4gh duo" and "data use ontology consent" found only the [GA4GH DURI website repo](https://github.com/ga4gh-duri/ga4gh-duri.github.io) (14★). No agent-side enforcement exists that I could find.

**Why Jerry:** Cross-functional bridge between science, legal/compliance, and engineering; GxP mindset; MCP/RBAC from earlier ideas can be reused conceptually.

**MVP:** Python library + MCP middleware; DUO term parser; purpose declaration (`research_purpose`) from the agent; allow/deny/needs-review decisions with machine-readable rationale; demo against a mock dataset catalog; policy test fixtures.

**Career angle:** Positions Jerry at the intersection of responsible-AI and genomic data governance.

## 5. `agent-esign` — Part 11-style electronic-signature approvals for agent actions via MCP multi-round-trip input
**Pitch:** Human approval step for risky agent actions that captures a signature manifestation (signer, meaning, timestamp) linked to the exact action payload hash.

**Problem & who needs it:** 21 CFR Part 11 §11.50/§11.70 require signature manifestations bound to records. Agent "approve?" prompts today are ephemeral UI clicks with no durable, record-linked evidence.

**Why now:** The new MCP Multi Round-Trip Requests pattern and Tasks `tasks/update` (client-to-server input) make server-side approval gates a first-class protocol flow ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)).

**Prior art & gap:** The e-signature repos found are toy-level or full platforms: [hahsahsay-design/part11-esign](https://github.com/hahsahsay-design/part11-esign) (0★, SaaS), [gampers/kpbma-ai-csv](https://github.com/gampers/kpbma-ai-csv) (0★, sandbox). None integrate with MCP/agent approvals. Complements (does not duplicate) `agent-ledger`, which records the session audit trail.

**Why Jerry:** Business Process Manager/validation lead for GxP systems; Claude Code engineering.

**MVP:** MCP server that wraps a "protected" tool: returns `input_required` with an approval request; verifies identity via OIDC re-auth; signs `{action_hash, signer, meaning, time}` (Ed25519), appends to hash-chained store; reference demo gating an S3 delete or pipeline release; a Part 11 mapping doc (clearly stating limits — it supports, not guarantees, compliance).

**Career angle:** Very specific, rare combination of agent engineering and regulated e-record knowledge.

## 6. `mcp-sfn-tasks` — Stateless MCP server template with Tasks backed by Step Functions on AWS
**Pitch:** Reference implementation of an MCP 2026-07-28 server on Lambda/Fargate where long-running jobs (alignments, pipeline runs) are Tasks backed by Step Functions + DynamoDB.

**Problem & who needs it:** The stateless spec removes sessions, so long-running work must use explicit handles — ideal for serverless but few examples exist. Bioinformatics tools are the canonical long-running use case.

**Why now:** [Spec 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog) (stateless core, Tasks extension with polling), with the Tasks-auth gap flagged by [Mindgard](https://mindgard.ai/blog/zero-auth-zero-trust-the-must-that-never-made-it-into-mcps-new-tasks-extension).

**Prior art & gap:** Searches for "mcp tasks step functions" and "mcp stateless lambda" returned no repos. [awslabs/mcp](https://github.com/awslabs/mcp) (9.9k★) has many servers but I did not verify whether any implement the new Tasks extension. Differentiator: includes an authorization check binding task handles to the requesting principal (the gap in the spec text). Distinct from `nf-ops-mcp` (11/12), which is about triaging Nextflow runs.

**Why Jerry:** AWS Batch/IAM/Terraform expertise; MCP/Claude Code; infra-first mindset.

**MVP:** Terraform (API Gateway/Lambda, Step Functions, DynamoDB); TypeScript or Python handler implementing `server/discover`, `tools/call` returning task handle, `tasks/get`, `tasks/update`; principal-bound handles; one demo tool (FastQC on S3 object via Batch); conformance checks against the official SDK.

**Career angle:** Early, concrete expertise on the new MCP spec plus secure serverless agent infrastructure.

## Summary
Today's six ideas center on the MCP 2026-07-28 spec, the HealthOmics/Nextflow 26.x changes, and the unvalidated growth of bioinformatics agent skills: **`bioskill-lint`** (static validation of bio agent skills), **`nf-strict-migrate`** (agent-assisted Nextflow strict-syntax migration with HealthOmics preflight), **`omics-iceberg`** (Terraform-packaged VCF → S3 Tables cohort store with fidelity verification), **`duo-guard`** (GA4GH DUO consent enforcement for agents), **`agent-esign`** (Part 11-style signed approvals via MCP multi-round-trip input), and **`mcp-sfn-tasks`** (stateless MCP server template with Tasks on Step Functions). Caveats: GitHub searches are keyword-based, so "nothing found" means nothing found by those queries; regulatory-status claims come from secondary sources and should be verified before citing.
