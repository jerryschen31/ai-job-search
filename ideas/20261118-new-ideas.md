## 1. `nf-agent-audit` — Policy lint and signed audit report for Nextflow `agent` runs
**Pitch:** Read Nextflow's own lineage records for agent steps and produce a policy check plus a reviewer-ready evidence report (models, prompts, tools, skills, inputs, outputs), failing CI if a pipeline violates a declared policy.

**Problem & who needs it:** Nextflow now lets a pipeline call an LLM agent inside a workflow. Regulated groups (GxP bioinformatics, clinical genomics) need to answer: which model, which prompt, which tools (was `shell:bash` enabled?), which skills version, and what did it return. The `AgentRun` lineage data exists, but nothing turns it into an approvable record or enforces rules like "pi runner only, no shell tool, pinned model ID, skills pinned to a git rev."

**Why now:** Agents landed in 26.10.0 as a preview (<https://docs.seqera.io/nextflow/agent>). The docs state runs are recorded as `AgentRun` lineage records including runner, model, instruction, prompt template, output schema, tools, skills and inputs. Remote skills can be referenced by `github.com/<org>/<repo>[@rev]`, so an unpinned revision is a real compliance hazard. Preview status means early tooling can shape practice.

**Prior art & gap:** Examples only: [embedbio/nextflow-agents](https://github.com/embedbio/nextflow-agents) (0 stars, a port of upstream examples), [habicht12/nextflow-codex-adapter](https://github.com/habicht12/nextflow-codex-adapter) (0 stars, a runner adapter). Nothing found for governance, linting or audit reporting of agent steps. Generic MCP security scanners exist (e.g. [Tencent/AI-Infra-Guard](https://github.com/Tencent/AI-Infra-Guard), 7,550 stars) but don't understand Nextflow lineage or GxP evidence. Gap: pipeline-native, regulated-use reporting.

**Why Jerry:** Led GxP-qualified Bioinformatics Cloud validation at Genentech; knows what an auditor asks for. Daily Claude Code / agentic engineering, plus Nextflow-on-AWS background.

**MVP (2–4 weeks):** (1) a YAML policy file (allowed runners, tool allow-list, model allow-list, skill-rev pinning, max iterations); (2) a Python CLI that parses `nextflow lineage`/config output for a run and checks the policy; (3) a Markdown/PDF evidence report with content hashes of prompts and schemas; (4) optional sigstore/cosign signing of the report; (5) a GitHub Action and a demo pipeline with a deliberately bad agent config. Stack: Python, Pydantic, Nextflow 26.10+, Jinja2, cosign.

**Career angle:** Concrete proof of "governed agentic AI in regulated pipelines", the exact gap enterprises hit when moving from pilots to production; very relevant to biotech-AI platform/validation roles.

## 2. `census-mcp` — Pinned, provenance-stamped MCP server for the CELLxGENE Census
**Pitch:** An MCP server that lets an agent query the Census only against a pinned LTS release, and stamps every answer with release, query filters, and cell counts so results are reproducible.

**Problem & who needs it:** Agents querying "latest" single-cell data give answers that silently change week to week. Computational biologists and translational teams want agent-assisted atlas exploration (cell-type composition, marker lookups, dataset discovery) whose answers can be reproduced and cited in a report.

**Why now:** Census LTS releases are published every six months and retained at least five years, with a weekly "latest" that is retained only briefly (<https://chanzuckerberg.github.io/cellxgene-census>); data lives on AWS Open Data (<https://registry.opendata.aws/biohub-cellxgene-census/>). MCP 2026-07-28 makes stateless servers easy to run serverlessly. CZI's virtual-cell push (<https://biohub.org/blog/ai-cell-models-platform-release/>) increases demand for agent access to atlas data.

**Prior art & gap:** [longevity-genie/cellxgene-mcp](https://github.com/longevity-genie/cellxgene-mcp) (3 stars, last push 2025-06), [QuentinCody/cellxgene-mcp-server](https://github.com/QuentinCody/cellxgene-mcp-server) (0 stars, wraps the Discover API), [biocontext-ai/anndata-mcp](https://github.com/biocontext-ai/anndata-mcp) (7 stars, AnnData metadata only). The official [chanzuckerberg/cellxgene-census](https://github.com/chanzuckerberg/cellxgene-census) has 130 stars and no MCP surface that I found. Gap: nothing built around release pinning, bounded SOMA queries, and provenance output.

**Why Jerry:** Single-cell genomics platform lead at Factorial; Ph.D. computational biology; MCP/agent-skills fluency.

**MVP (2–4 weeks):** Tools for `list_datasets`, `cell_type_counts`, `gene_expression_summary` (aggregations only, with row caps and no full-matrix pulls), and `export_query_manifest`. Every response embeds `{census_version, filters, n_obs, query_hash}`. Include a replay command that re-runs a manifest. Stack: Python, `cellxgene-census` + TileDB-SOMA, official MCP Python SDK, pytest golden queries, optional Lambda deployment.

**Career angle:** A public, useful biotech MCP server demonstrating reproducibility discipline, a differentiator over "demo" servers.

## 3. `mcp-lock` — Change control for MCP servers and agent skills (lockfile + impact assessment)
**Pitch:** `package-lock` for the agent toolchain: pin every MCP server's tool schemas and every skill's content hash, diff on upgrade, and generate a change-control impact assessment.

**Problem & who needs it:** In a validated environment, a tool description or schema change on an MCP server is a change to a computerized system. Teams need to detect drift, classify it (cosmetic, additive, breaking, behavioral), and attach an impact assessment to a change record before the new version is allowed.

**Why now:** The 2026-07-28 spec introduces a feature lifecycle with Active/Deprecated/Removed states and a minimum 12-month deprecation window, and deprecates Roots, Sampling and Logging (<https://blog.modelcontextprotocol.io/posts/2026-07-28/>). Servers will be changing across versions while regulated teams must keep control. GAMP AI guidance emphasizes change management (<https://ispe.org/pharmaceutical-engineering/may-june-2026/innovation-and-regulation-danish-medicines-agency-insights>).

**Prior art & gap:** Security scanners such as [Tencent/AI-Infra-Guard](https://github.com/Tencent/AI-Infra-Guard) (7,550 stars) scan for malicious tools. My searches for schema pinning/drift tooling returned nothing relevant, though the search tool is coarse, so check again before starting. Gap: GxP-style change classification and impact assessment, not threat detection.

**Why Jerry:** Business Process Manager for Basecamp 2.0 and global implementation lead for validated deployments, so change control is lived experience. Wrote Claude Code skills/MCP tooling.

**MVP (2–4 weeks):** `mcp-lock init/verify/diff` against stdio and HTTP servers; JSON lockfile (tool names, JSON schemas, description hashes, server version, spec version); diff classifier; an LLM-assisted (Claude) impact-assessment draft that a human approves; GitHub Action that blocks merges on unapproved drift. Stack: Python or TypeScript, MCP SDK, JSON Schema diffing, Claude API.

**Career angle:** Fits "AI platform engineering in regulated enterprise" and "AI governance" roles; small, sharp, and easy for others to adopt.

## 4. `refdata-lock` — Immutable, attested reference genome and annotation store on S3
**Pitch:** Terraform + CLI for a write-once reference data bucket (genomes, indices, annotations, container-free assets) with manifest hashes, Object Lock, and a Nextflow-readable resolver that refuses unregistered references.

**Problem & who needs it:** "Which GRCh38 and which GENCODE did that run use?" is a recurring audit and reproducibility question. Teams copy iGenomes-style assets across buckets and indices get rebuilt with drifting tool versions. Platform teams need a controlled, versioned, verifiable reference source.

**Why now:** [refgenie/refgenie](https://github.com/refgenie/refgenie) is still active (pushed 2026-11-17) and has a [Nextflow plugin](https://github.com/refgenie/refgenie_nfcore), and a community registry [refgenie-registry](https://github.com/refgenie/refgenie-registry) is being updated, showing live demand for reference management. Nextflow 26.10 ships nf-amazon 3.12.0 (<https://docs.seqera.io/changelog/tags/nextflow>) for S3-centric runs.

**Prior art & gap:** refgenie (74 stars) manages and serves assets but is not designed around immutability, S3 Object Lock, or attestation; [refgenieserver](https://github.com/refgenie/refgenieserver) (12 stars, last push 2026-04) is a serving layer. Gap: a compliance-oriented, cloud-native control plane. This differs from earlier `omics-attest` (output evidence) because it governs *inputs*.

**Why Jerry:** Built the cloud genomics data solution at Encoded (7,000+ samples) and a GxP Bioinformatics Cloud; Terraform/S3/IAM are core skills.

**MVP (2–4 weeks):** Terraform module (versioned bucket, Object Lock, bucket policy, KMS, access logging); `refdata register` that hashes files, writes a signed manifest and tags; Nextflow config snippet/helper that resolves `genome` params to verified manifests and checks hashes on stage-in; nf-test example. Stack: Terraform, Python, boto3, Nextflow, cosign.

**Career angle:** Shows cloud-infra-for-science discipline and a reusable component for any validated bioinformatics platform.

## 5. `nf-rightsize` — Resource right-sizing recommendations from Nextflow trace history
**Pitch:** Ingest Nextflow trace files across runs, compute per-process memory/CPU/time distributions, and emit a reviewed `resources.config` plus retry-ladder suggestions for AWS Batch.

**Problem & who needs it:** Over-requested memory wastes Batch spend; under-requested causes OOM retries. Most teams guess or copy nf-core labels. Platform engineers want a data-driven, reviewable config change with a quantified savings estimate.

**Why now:** Nextflow 26.10 adds run-level `cpus`/`memory` limits for grid executors and typed-pipeline improvements (<https://docs.seqera.io/changelog/tags/nextflow>); the static-typing and lint momentum drives pipeline modernization where config hygiene is revisited. Cost scrutiny of cloud genomics is persistent.

**Prior art & gap:** My GitHub searches (`nextflow resource optimization trace`, `aws batch cost`) found nothing relevant; the only hit was a 2018, 1-star [AWS Batch cost estimator](https://github.com/wsmcil/aws_batch_cost_estimator). Seqera Platform has optimization features I could not verify as open source, so I do not rely on that. Differs from earlier `omics-finops` (cost attribution) by recommending configuration, not reporting spend.

**Why Jerry:** Operated AWS Batch pipelines at scale; practical with trace data and cost tradeoffs.

**MVP (2–4 weeks):** CLI parsing `trace.txt`/`-with-trace` outputs (optionally from S3); per-process p95/p99 of `peak_rss`, `realtime`; recommendation rules with safety margin; output config with `task.attempt`-scaled retries; markdown diff showing projected savings; validate on public nf-core test runs. Stack: Python, pandas/DuckDB, Nextflow, Jinja2.

**Career angle:** Pragmatic platform-engineering win with measurable dollars saved; good talking point for infra roles.

## 6. `nf-bio-agents` — Tested, skill-backed Nextflow agent modules for bioinformatics operations
**Pitch:** A small library of Nextflow agent modules (failed-task diagnosis, params/samplesheet sanity explanation, tool-version change summary), each with `SKILL.md` instructions, least-privilege tool lists, and replay-based eval fixtures.

**Problem & who needs it:** Nextflow agents shipped, but there is no body of vetted agent modules for bioinformatics. Pipeline owners want safe, read-only helpers (explain a failed run, summarize QC anomalies in plain language) with known tool scopes and tests, not ad hoc prompts.

**Why now:** Agent modules can carry their own skills and tools directories and run via `nextflow module run` (<https://docs.seqera.io/nextflow/agent>); the 26.04 release added a module registry (<https://seqera.io/blog/nextflow-26-04>). The first ecosystem content will define conventions.

**Prior art & gap:** Only examples and adapters (0 stars): [embedbio/nextflow-agents](https://github.com/embedbio/nextflow-agents), [cheahhl814/BettaMt-agents](https://github.com/cheahhl814/BettaMt-agents) (1 star, one organism's pipeline). Earlier ideas (`nf-ops-mcp`, `qc-verdict`) use MCP/external services; this one lives inside the pipeline with the native primitive. Pairs with idea 1 for governance.

**Why Jerry:** Claude Code skills author and AI trainer; bioinformatics pipeline operator.

**MVP (2–4 weeks):** Three modules with read-only `fs:*` tools on the `pi` runner; structured JSON output schemas; fixtures of recorded failure logs (anonymized) with expected diagnoses; a pytest/nf-test eval that scores outputs and flags regressions across models; README documenting scope and limits. Stack: Nextflow 26.10+, nf-agent-pi, Claude models, Python for evals.

**Career angle:** Early, visible contribution to the Nextflow agent ecosystem, demonstrating agent-in-pipeline engineering with evaluation discipline.
