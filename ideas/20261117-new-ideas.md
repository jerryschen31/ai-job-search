## 1. `nf-test-forge` — Agent that writes and maintains nf-test suites for Nextflow pipelines
**Pitch:** An agent skill plus CLI that generates nf-test files and snapshots for modules and workflows, flags unstable snapshots, and reports coverage gaps. It targets in-house pipelines that don't have nf-core's test discipline.

**Problem & who needs it:** Every pipeline team in biotech has workflows with no tests, or tests that rot after strict-syntax and registry migrations. Under GxP, tests are the validation evidence. Writing nf-test files by hand is tedious, and snapshot determinism (timestamps, paths, md5 of non-deterministic outputs) is the part people get wrong.

**Why now:** nf-core completed the move to nf-test ([blog](https://nf-co.re/blog/2026/modules-pytest-conversion)). nf-core tools 4.0.0 and Nextflow 26.04 both force migration work ([4.0.0](https://nf-co.re/blog/2026/tools-4_0_0), [26.04](https://docs.seqera.io/nextflow/migrations/26-04)). nf-core's own docs say a fresh template test fails on first CI run until you generate a snapshot ([docs](https://nf-co.re/docs/developing/testing/overview)). The official agent-skills repo has no testing skill.

**Prior art & gap:** [nextflow-io/agent-skills](https://github.com/nextflow-io/agent-skills) (25 stars) has skills `create-workflow`, `install-nextflow`, `launch-workflow`, `migrate-nextflow-code`, and `run-module`. It has no test authoring. [bmds-tue/nf-claw](https://github.com/bmds-tue/nf-claw) (4 stars) is a pipeline library for agents. [biocorecrg/nf-llm-debugger](https://github.com/biocorecrg/nf-llm-debugger) (2 stars) diagnoses logs. `gh search repos "nf-test agent"` returned nothing relevant. The gap is deterministic-snapshot analysis plus test generation.

**Why Jerry:** He led GxP-qualified Bioinformatics Cloud validation, so he knows tests are evidence. He has Nextflow-on-AWS-Batch experience and Claude Code skills experience.

**MVP (2–4 weeks):**
- Week 1: parse `main.nf` and module signatures, then emit `*.nf.test` scaffolds.
- Week 2: run each test twice and diff snapshots to flag non-determinism. Suggest `nft-utils` helpers or ignore patterns.
- Week 3: coverage report listing untested processes and workflows.
- Week 4: Claude Code skill wrapper and a demo on 2 public nf-core pipelines.
- Stack: Python, nf-test, Nextflow, GitHub Actions.

**Career angle:** It is testing and validation automation for regulated pipelines. It gives a public, contributable artifact in the nf-core ecosystem.

## 2. `qc-verdict` — Versioned acceptance criteria over MultiQC, with an MCP front end
**Pitch:** It reads MultiQC's data output and evaluates it against versioned, signed-off acceptance criteria (YAML). It emits a structured pass/warn/fail verdict with evidence, which an agent can explain but cannot override.

**Problem & who needs it:** MultiQC reports are for humans to eyeball. In a regulated or clinical-adjacent pipeline, "QC passed" needs a documented, reproducible criterion that is version-controlled. Teams hand-roll scripts per project. An LLM summary is not a verdict.

**Why now:** MultiQC added AI summaries in v1.27 and Bedrock support in v1.29 ([v1.35 changelog](https://docs.seqera.io/changelog/multiqc/v1.35)), which shows demand for an AI layer. Nothing yet provides a deterministic gate under that layer. Community MCP servers for FastQC/MultiQC exist only as tiny wrappers.

**Prior art & gap:** [MultiQC/MultiQC](https://github.com/MultiQC/MultiQC) (1,505 stars) generates reports. [MultiQC/MegaQC](https://github.com/MultiQC/MegaQC) (97 stars, last pushed 2024-12) aggregates runs. [Babajan-B/BioQC-MCP](https://github.com/Babajan-B/BioQC-MCP) (1 star) and [bio-mcp/bio-mcp-fastqc](https://github.com/bio-mcp/bio-mcp-fastqc) (0 stars) just run the tools. The gap is a criteria-as-code evaluator with an audit-friendly verdict, plus MCP tools to query it.

**Why Jerry:** He built the end-to-end genomics pipeline for 7,000+ samples at Encoded Therapeutics. He knows what QC thresholds matter and has GxP validation experience.

**MVP (2–4 weeks):**
- Week 1: criteria schema (metric, threshold, scope, rationale, version) and a MultiQC `multiqc_data.json` reader.
- Week 2: verdict engine producing JSON and a Markdown evidence table.
- Week 3: MCP server (`get_verdict`, `explain_failure`, `list_criteria`) and a criteria-change diff.
- Week 4: sample criteria for bulk RNA-seq and WGS, plus an nf-core pipeline demo.
- Stack: Python, pydantic, MCP Python SDK, MultiQC JSON.

**Career angle:** It is a concrete deterministic-gate-around-LLM pattern, which is exactly what regulated AI teams want to see.

## 3. `sop2skill` — Compile controlled SOPs into versioned, traceable agent skills
**Pitch:** It converts a Markdown or Word SOP into a SKILL.md bundle. Each step carries a trace ID back to its SOP section, with a diff report when the SOP revises. This keeps the skill and the controlled document in sync.

**Problem & who needs it:** Pharma teams want agents to follow SOPs. Hand-written skills drift from the controlled document, and nobody can show which SOP version an agent run followed.

**Why now:** SKILL.md is now a cross-vendor standard with governance moving to a foundation ([TechRepublic](https://www.techrepublic.com/article/news-anthropic-agent-skills-foundation-handover/)). Practitioner commentary says governance around the skill, not the file, makes it enterprise-ready ([summary](https://atlan.com/know/what-are-enterprise-skills/)).

**Prior art & gap:** My searches (`gh search repos "SOP skills pharma"` and variants) returned no relevant repos. Generic scanners such as [NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector) (26,675 stars) check for malicious patterns, not for fidelity to a controlled document. This adjacent area is untested, so verify again before building.

**Why Jerry:** He is Department Lead AI Champion at Genentech, training about 100 people and building Claude Code tools. He also owns a Business Process Manager role and GxP validation.

**MVP (2–4 weeks):**
- Week 1: SOP parser (headings, numbered steps, roles) and trace-ID scheme.
- Week 2: skill generator with front matter recording SOP ID, version, and hash.
- Week 3: revision differ that reports changed steps and which skill sections are stale.
- Week 4: CI check that fails when the SOP hash and skill disagree. Include a sample non-confidential SOP.
- Stack: Python, markdown-it, python-docx, GitHub Actions.

**Career angle:** It sits at the intersection of AI adoption and document control, which is where regulated-industry AI roles are hiring.

## 4. `fastq-tier` — Restore-aware storage lifecycle for sequencing data on S3 (Terraform + Nextflow wrapper)
**Pitch:** Terraform for tiering raw FASTQ/BAM to Intelligent-Tiering or Glacier tiers, plus a Nextflow pre-step that detects archived inputs, issues restores, and waits, so pipelines never fail on `InvalidObjectState`.

**Problem & who needs it:** Genomics groups keep petabytes of raw data and want archive pricing, but archived objects break pipelines when someone re-runs a sample. They pick between paying too much and breaking runs.

**Why now:** AWS documents that Archive Access and Deep Archive Access tiers require an explicit restore, with Deep Archive taking up to 12–48 hours ([S3 docs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/archived-objects.html), [genomics whitepaper](https://docs.aws.amazon.com/whitepapers/latest/genomics-data-transfer-analytics-and-machine-learning/appendix-f-optimizing-storage-cost-and-data-lifecycle-management.html)). AWS's own [Architecture Blog](https://aws.amazon.com/blogs/architecture/genomics-workflows-part-4-processing-archival-data) describes the problem but ships no reusable code.

**Prior art & gap:** `gh search repos "glacier nextflow"` returned nothing, and `glacier fastq` returned nothing. The prior art is documentation, not tooling. A well-maintained Terraform module with a pipeline-aware restore step appears open.

**Why Jerry:** Terraform, S3, Batch, and cloud genomics at scale are his core stack from Encoded Therapeutics and Genentech.

**MVP (2–4 weeks):**
- Week 1: Terraform module (lifecycle rules by prefix and age, inventory, tags) with examples.
- Week 2: Python tool that scans a samplesheet and reports each input's storage class and restore cost and ETA.
- Week 3: Nextflow plugin or pre-run script that triggers restores and blocks the run until ready.
- Week 4: cost simulator using S3 inventory, plus a README with a worked example.
- Stack: Terraform, Python (boto3), Nextflow, S3 Inventory.

**Career angle:** It is cost-aware infrastructure for science, a visible signal for cloud and platform roles.

## 5. `agentcore-bio` — GxP-hardened Terraform blueprint for hosting biotech MCP servers on Bedrock AgentCore
**Pitch:** A Terraform reference deployment of AgentCore Runtime and Gateway for biotech MCP servers: private networking, IAM-scoped tool access, CloudTrail audit retention, and a validation evidence script.

**Problem & who needs it:** Biotech platform teams want to host internal MCP servers (LIMS, sequence DBs, pipeline ops) behind a managed gateway, but the generic modules don't address audit retention, data-residency, or qualification evidence.

**Why now:** AgentCore added stateful MCP on Runtime ([Mar 2026](https://aws.amazon.com/ru/about-aws/whats-new/2026/03/amazon-bedrock-agentcore-runtime-stateful-mcp/)), GovCloud availability ([May 2026](https://aws.amazon.com/pt/about-aws/whats-new/2026/05/bedrock-agentcore-launch-aws-govcloud-us/)), and Gateway support for MCP 2026-07-28 ([post](https://aihub.hkuspace.hku.hk/?p=7843)).

**Prior art & gap:** [aws-samples/sample-agentcore-enterprise-platform](https://github.com/aws-samples/sample-agentcore-enterprise-platform) (27 stars) and [aws-ia/terraform-aws-agentcore](https://github.com/aws-ia/terraform-aws-agentcore) (25 stars) are generic. [aws-samples/sample-agentcore-scverse](https://github.com/aws-samples/sample-agentcore-scverse) (2 stars) is a single-cell sample. None address qualification evidence or life-science controls. Check overlap with the earlier `omics-mcp-gateway` idea: that one is the gateway logic, while this one is the infrastructure blueprint.

**Why Jerry:** Terraform, IAM, and AWS architecture are his core stack. He delivered the GxP-qualified Bioinformatics Cloud and writes validation evidence for a living.

**MVP (2–4 weeks):**
- Week 1: VPC, endpoints, KMS, and IAM baseline module.
- Week 2: deploy a sample read-only bio MCP server on AgentCore Runtime and put the Gateway in front.
- Week 3: CloudTrail and log retention, with an evidence script that exports configuration snapshots for IQ.
- Week 4: README with a control-mapping table and teardown.
- Stack: Terraform, AgentCore, Python MCP SDK, CloudTrail.

**Career angle:** It shows regulated-cloud and agent-platform skills together, which suits platform engineering roles in pharma.

## 6. `bio-inject-bench` — Prompt-injection test corpus and scanner for genomics metadata ingested by agents
**Pitch:** A corpus of poisoned FASTA headers, VCF `##` lines, GEO/SRA descriptions, and sample-sheet fields, plus a harness that tests whether your agent follows embedded instructions.

**Problem & who needs it:** Agents that curate public datasets or read lab metadata ingest free-text fields nobody sanitizes. Existing scanners look at skills and code, not at scientific file content.

**Why now:** The CSA note on agent data injection names metadata as the attack surface, with reported success rates of roughly 31–43% on structured JSON ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-agent-data-injection-attack-class-20260718/)). It does not cover scientific data. Snyk flags bioinformatics skills for third-party content exposure ([example](https://skills.sh/jimmc414/kosmos/biomni/security/snyk)).

**Prior art & gap:** [NVIDIA/SkillSpector](https://github.com/NVIDIA/SkillSpector) (26,675 stars), [HeadyZhang/agent-audit](https://github.com/HeadyZhang/agent-audit) (246 stars), and [sinewaveai/agent-security-scanner-mcp](https://github.com/sinewaveai/agent-security-scanner-mcp) (123 stars) scan skills, code, and configs. `gh search repos "agent prompt injection genomics"` returned nothing. I found no domain-specific corpus.

**Why Jerry:** He builds agentic tools with Claude Code in a regulated setting and works with these file formats daily. It also complements his SRA curation and skill-validation interests.

**MVP (2–4 weeks):**
- Week 1: threat model and 30 seed payloads across FASTA, VCF, GFF, SRA/GEO, and samplesheet formats.
- Week 2: generator that injects payloads into real small public files.
- Week 3: harness that runs an agent (Claude Code headless or API) on a task and checks for canary-triggered behavior.
- Week 4: results report and a recommended sanitizer or filter.
- Stack: Python, pysam or biopython, Claude API or Claude Code headless, pytest.

**Career angle:** It is AI security in a niche nobody covers, which suits a Genentech-style AI-governance conversation and gives a public research-style artifact.
